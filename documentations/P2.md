# P2 — Discovering a VXLAN

---

## Overview

Build on the routing stack from P1 to implement a VXLAN overlay (VNI=10) between two routers — first with static unicast remote VTEP addresses, then with dynamic multicast. Two hosts connected to the routers must be able to ping each other across the tunnel.

### Objectives
1. **Static Mode**: Set up VXLAN manually — each VTEP hard-codes the remote peer IP
2. **Dynamic Multicast Mode**: Replace static config with a multicast group so VTEPs discover each other automatically

### Core Requirements
- VNI = `10`, interface named `vxlan10`
- Bridge interface named `br0`
- Multicast group (dynamic mode): `239.1.1.1`
- Node names must include login (e.g., `router_yilin`)
- All code in `/P2` at repo root — include both static and dynamic config files, commented

## Concepts

### What VXLAN does

```
host_yilin-1 sends L2 frame
       │
  router_yilin-1 (VTEP)
  wraps: [ outer IP | UDP port 4789 | VXLAN header (VNI=10) | inner Ethernet frame ]
       │
  router_yilin-2 (VTEP)
  unwraps → delivers inner frame to br0 → host_yilin-2
```

The hosts think they are on the same Ethernet segment — the tunnel is invisible to them.

### Key objects

| Object | Role |
|---|---|
| `vxlan10` | VXLAN interface — VNI 10, UDP encapsulation/decapsulation on port 4789 |
| `br0` | Linux bridge — L2 switch connecting host-facing `eth1` and `vxlan10` |
| `eth0` | Underlay interface — carries the UDP tunnel between routers |
| `eth1` | Overlay interface — connects to host, added to `br0` |

### Static vs multicast

| Mode | Remote VTEP discovery | Command |
|---|---|---|
| Static | Hard-coded peer IP — unicast tunnel between exactly 2 VTEPs | `remote <peer_ip>` |
| Multicast | VTEPs join a group — BUM traffic floods to all members | `group 239.1.1.1 dev eth0` |

## Static mode configuration

On **router_yilin-1** (`eth0` = `30.1.1.1/24`):

```sh
# Assign underlay IP
ip addr add 30.1.1.1/24 dev eth0
ip link set eth0 up

# Create VXLAN interface pointing to peer VTEP
ip link add vxlan10 type vxlan id 10 remote 30.1.1.2 dstport 4789 dev eth0

# Create bridge and attach overlay eth + vxlan
ip link add br0 type bridge
ip link set eth1 master br0
ip link set vxlan10 master br0

# Bring everything up
ip link set vxlan10 up
ip link set br0 up
ip link set eth1 up
```

On **router_yilin-2** (`eth0` = `30.1.1.2/24`): same commands with `remote 30.1.1.1`.

> Hosts connect to `br0` through `eth1` of the router — they are **bridged**, not routed. Assign host IPs in any subnet; they only need L2 reachability through the tunnel.

---

## Dynamic multicast configuration

Replace `remote <ip>` with `group` pointed at the underlay interface:

```sh
ip link add vxlan10 type vxlan id 10 group 239.1.1.1 dstport 4789 dev eth0
```

Both routers use the same multicast group — the kernel joins it automatically. All other bridge/link-up commands are identical to static mode.

## Verification

```sh
# Check VXLAN interface details
ip -d link show vxlan10

# Check bridge membership
brctl show br0

# Check learned MACs (should appear after ping)
brctl showmacs br0

# Ping between hosts
ping <host2_ip>
```

In Wireshark on the link between routers — filter `vxlan`:
- Outer UDP packets to port 4789
- VXLAN header with VNI = 10
- Inner Ethernet frames (ICMP between hosts)
