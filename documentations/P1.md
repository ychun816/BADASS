# P1 — GNS3 Configuration with Docker

---

## Overview

Configure and deploy GNS3 with Docker in a virtual machine. Create and integrate two Docker images (a host and a router) to build a functional baseline routing stack.

### Objectives
1. **Environment Setup**: Install and configure GNS3 and Docker within the VM
2. **Host Image**: Plain `alpine:latest` — no Dockerfile, just `docker pull alpine:latest`
3. **Router Image**: Alpine-based image with FRR (bgpd, ospfd, isisd, staticd, zebra) + debug tools
4. **Topology Deployment**: Instantiate images in GNS3, connect them, verify console access

### Core Requirements
- **Host**: Alpine (or equivalent) — no IP configured by default
- **Router**: Must include FRR with `bgpd`, `ospfd`, `isisd`, `staticd`, and `zebra` active
- **No IP addresses** configured by default inside images — set per topology at runtime
- **Naming**: GNS3 node names must include your login (e.g., `router_yilin`, `host_yilin`)
- **Deliverables**: All code in `/P1` at repo root. Include exported `.zip` with portable base images and commented config files

## FRR Daemon Concepts

### How FRR works

```
Dockerfile → docker build → docker image → GNS3 appliance → container node
```

```
bgpd    ─┐
ospfd   ─┤──► zebra ──► Linux kernel routing table ──► network interface
isisd   ─┤
staticd ─┘
```

| Daemon | Role |
|---|---|
| `zebra` | Mandatory base; translates routing decisions into kernel routes via Netlink |
| `bgpd` | BGP sessions and route advertisements between Autonomous Systems |
| `ospfd` | OSPF link-state routing within an AS |
| `isisd` | IS-IS — link-state protocol similar to OSPF, used in large ISP networks |
| `staticd` | Manages static routes in FRR |

Daemons are enabled at build time via `sed` on `/etc/frr/daemons`.

### zebra vs ubridge

| | `zebra` | `ubridge` |
|---|---|---|
| **What it is** | FRR daemon (part of the router image) | Standalone C binary (installed on the VM host) |
| **Where it runs** | Inside the Docker container (router node) | On the GNS3 host, called by `gns3server` |
| **Layer** | L3 — programs kernel routing/forwarding table | L2 — bridges raw packets between virtual interfaces |
| **Purpose** | Translates BGP/OSPF/IS-IS decisions into kernel routes via Netlink | Connects GNS3 nodes together by forwarding frames between their virtual links |
| **Who calls it** | Other FRR daemons (`bgpd`, `ospfd`, `isisd`) | GNS3 server (as a subprocess per link) |
| **Privileges** | Runs as the `frr` user inside the container | Needs `cap_net_admin` + `cap_net_raw` via `setcap` |
| **Relevant to** | Routing inside a single node | Physical topology wiring between nodes |

In short: `zebra` decides where packets go inside a router; `ubridge` is the wire that connects routers together in GNS3.

### GNS3 Docker integration
- GNS3 pulls the image by name and starts it as a container per node
- Each node gets its own network namespace — interfaces are `eth0`, `eth1`, ... per link
- Console access via telnet to a port GNS3 allocates (shown in topology panel)
- **No persistent storage**: every container restart resets to image state

## GNS3 Setup

### Install prerequisites (in VM as root)

The GNS3 Server is a Python application. No official `.deb` packages exist for Debian — pip inside a virtualenv is the safest install method. The GNS3 GUI is distributed as an AppImage.

> You need **both**: the server (via pip/venv) handles backend emulation; the GUI (AppImage) is the frontend. Running the AppImage alone does nothing without a running server.

### SSH & user setup (avoid running GNS3 as root)

```bash
# SSH into VM from local machine
ssh root@127.0.0.1 -p 2223

# Add user to sudo group
sudo usermod -aG sudo yilin

# Exit and re-SSH as your user
exit
ssh yilin@127.0.0.1 -p 2223

# Verify
groups
sudo whoami    # should print: root
```

### GNS3 setup steps in topology

1. **Add host image**: Edit → Preferences → Docker containers → New → `alpine:latest`
2. **Add router image**: same → `yilin-router` (after building above)
3. **Set console type**: `telnet` for both
4. **Set adapters**: 1 for host, 2+ for router (one per link)
5. **Drag nodes** onto canvas, link `host_yilin` ↔ `router_yilin`
6. **Start nodes**, right-click → Console
7. **Verify router**: `ps` should show `zebra`, `bgpd`, `ospfd`, `isisd`, `staticd`

### Verify GNS3 server & GUI

```bash
# After running install script, reload PATH
pipx ensurepath
source ~/.bashrc

# Launch GNS3 GUI
gns3

# Check server process
ps aux | grep gns3server

# Check listening port
sudo ss -tulnp | grep 3080

# Test API
python3 -m pipx run gns3server --version

# View server logs
tail -f ~/.config/GNS3/3.0/gns3_server.log
```

### Core Concepts

| Concept | Explanation | Why It Matters in BADASS |
|---|---|---|
| **BGP** | EGP that exchanges routes between Autonomous Systems | Needed to simulate AS-level routing between Docker routers |
| **Autonomous System (AS)** | A network under a single admin domain with a unique AS number | Each router belongs to an AS (e.g., 65001) |
| **eBGP vs iBGP** | eBGP – between different AS; iBGP – inside same AS | Determines neighbor config in topology |
| **Neighbor / Peer** | BGP router with which you exchange routes | Must configure properly in `bgpd` for route propagation |
| **AS Path** | List of AS numbers a route has passed | Prevents routing loops; shows the route path |
| **Next-Hop** | IP address for packet forwarding | Must be reachable for routes to work |
| **BGP FSM States** | Idle → Connect → Active → OpenSent → OpenConfirm → Established | "Established" is required for routing to work |
